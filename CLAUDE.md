# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

YeRide website — a static marketing, pre-registration, and fare-estimate site for a community-driven ridesharing platform. Astro 5, static output, deployed to GitHub Pages at https://www.yeride.com.

## Commands

```bash
npm run dev        # Dev server at http://localhost:4321
npm run checks     # Gate controls + route parity + copy gate + env-example + deploy-env parity (no deps)
npm run test:gates # The seven control sets alone (also run first by npm run checks)
npm run build      # npm run checks + env check + astro check + astro build → dist/ + dist copy gate
npm run preview    # Preview production build locally
```

No test runner and no linter are configured, and `npm run build` is the only automated verification gate. Alongside it sit seven sets of unit-style controls, plain Node, no deps, collected under `npm run test:gates` — which **`npm run checks` now runs first** (#83), so they run on every PR rather than only when someone remembers. Run them alone with `npm run test:gates`; each still names the file whose change should make you read it:

- `node scripts/copy-gate-patterns.test.mjs` — **read it whenever `scripts/copy-gate-patterns.mjs` changes** (#75). Its second list is the valuable half: a locked-price pattern is easy to widen and easy to widen too far, and every "must not fire" entry is real copy from this site. #82 added two further layers, and they cover the one field that can make a gate say *less* — `permits`, §5's permitted-exception mechanism. They spawn **`check-copy-gate.mjs` and `check-dist-copy-gate.mjs` themselves** over fixture trees, for the reason `copy-gate-suspension.test.mjs` does: each gate calls the withdrawal itself, so "the reader withdraws" is not evidence that either gate does, and "the source gate does" is not evidence about the shipped-output gate. Every bound has a positive control — delete any one of them and a named control fails.
- `node scripts/copy-gate-normalise.test.mjs` — **read it whenever `scripts/copy-gate-normalise.mjs` changes** (#80). Same shape and the same reason the second list matters: a normalisation is easy to widen too far, and over-reach here fails the build on text nobody wrote. Every invisible character in it is built from a numeric code point rather than typed or escaped, because editors and agent tools rewrite a backslash-u escape into the character on save, which turns a control into an unreviewable byte — or, when the byte is lost, into a test that passes because it no longer tests anything. #99 added the tag-**opening** controls to both lists and a small end-to-end layer with them, spawning `check-dist-copy-gate.mjs` over a fixture bundle for #83's reason — a claim behind a minified `r<t.length` must still be caught, and the same comparison must not weld a §5 phrase out of identifiers nobody wrote. It also added a **third** list, and that one is the lesson: #99's first revision claimed every bound of `TAG_OPEN` was held by a control, and its review found three that were not — deleting the doctype branch, deleting the processing-instruction branch, or dropping an end-of-input terminator each left every control green. Two were observable but not through a §5 match, since neither a doctype nor an XML declaration contains a forbidden word or splits a claim; they decide whether their own bytes are **dropped or left in the text**, which is what `VIEW_TEXT` reads. The third could not be observed by anything — with no `>` after it the scan fails either way — so that bound was **deleted rather than documented**. Every bound that can change an outcome now fails a named control when removed; the single refinement that cannot, `<?` followed by a non-letter, is recorded as such rather than counted as covered.
- `node scripts/copy-gate-suspension.test.mjs` — **read it whenever `scripts/copy-gate-suspension.mjs` changes** (#83). It covers the one rule in `check-copy-gate.mjs` that reads *data* rather than copy: whether a charge has been filed into the suspended pass-through family. That rule was written to match double quotes only, so `family: 'passthrough'` would have shipped copy-map §3.4's suspended "at cost" and insurance claims off a green build. It runs in **two layers**, and the second is the one that matters: the first covers the reader alone — every string-literal syntax, in the quote styles this repo does not use — while the second **spawns `check-copy-gate.mjs` itself** over a temporary fixture tree, because the reader being right is not the claim. Between reader and claim sit the arming condition (a `#48` pragma in a suspension-scoped file), the comment-stripping pass and the import wiring; a review proved the point by deleting the rule's `errors.push`, after which every reader-level control still passed. The fixture is a temp directory, never the real tree — an earlier draft read the real `feeLabels.ts` **raw** where the gate reads it comment-stripped, so an ordinary explanatory comment failed the build on data the gate correctly ignores. The end-to-end layer also pins the guard failing **closed** (a renamed or deleted `feeLabels.ts` is an error naming the cause) and staying **silent** once no `#48` pragma is outstanding, so the suspension can actually be retired.
- `node scripts/copy-gate-files.test.mjs` — **read it whenever `scripts/copy-gate-files.mjs` changes** (#81). It covers which files get the **tag views**, a rule with a cost on both sides, so both of its lists matter. Must-fire: a tag-split claim in `public/*.json`, `*.txt` and `*.webmanifest`, and — the case #81 was filed over — in a `dist/_astro/*.js` bundle, since `/fees` renders its rows client-side and its copy exists nowhere else. Must-**not**-fire: ordinary TypeScript, because in a `.ts` a `<` opens a generic and reading it as a tag deletes what it swallows and welds the words either side (`Map<string, Record<Lang, ReadonlyArray<X>>>` between a noun and an adjective is the fixture). Both gates are **spawned** over temp fixture trees for #83's reason — a table being right is not the claim. The dist half asserts what the gate **reports**, not its exit code: that gate's `ALLOWED` list is keyed to real built paths, so any synthetic tree exits 1 regardless and the exit code would prove nothing.
- `node scripts/copy-gate-pragma.test.mjs` — **read it whenever `scripts/copy-gate-pragma.mjs` changes** (#100). It covers the `copy-gate-allow` escape hatch itself — the one mechanism in either gate whose job is to make the build say *less*. The old rule asked whether a comment opener appeared **anywhere earlier on the line**, and a URL contains `//`, so the thing its own source comment said it prevented was not prevented: `<p data-src="https://x.test/a">Rides at cost. copy-gate-allow: ok #99</p>` passed and printed itself as an allowance. The rule is now **position, not presence** — the pragma must be the first thing in its comment. Two layers again, and for #83's reason: the reader alone, then **`check-copy-gate.mjs` spawned** over a temp fixture tree running that exploit line byte for byte, because a reader returning the right answer into a caller that ignores it is the failure the second layer exists to catch. Its second list is the valuable half, as ever: eleven pragma shapes that **must stay accepted**, since over-reach here rejects a correctly written allowance and fails the build on copy nobody may edit. All eleven live pragmas already open their own `//`, so nothing in `src/` had to change. One shape was **deliberately removed** rather than preserved — the trailing inline `foo, // copy-gate-allow: …`, whose introducing `//` is the hardest of all to tell from shipped text, which is the defect itself; no live pragma used it and the failure footer no longer advertises it. A pragma still covers both its own line and the line below, and that pairing is now pinned by a control, because the footer, `judge` and item 2 above are three places that have to agree.
- `node scripts/astro-prose.test.mjs` — **read it whenever `scripts/astro-prose.mjs` changes** (#88). It covers the newest gate, item 5, and it is the only control set here whose subject has **no live user of its escape hatch** — the one case #79 named for it dissolved when #39 put `redirect.astro` through `BaseLayout` — so the hatch is proved here or it is not proved at all. Two layers, for #83's reason: the reader alone, then **`check-astro-prose.mjs` spawned** over temp fixture trees. Its second list is the valuable half, as ever, and every entry is real syntax from this repo — frontmatter, a `<script>` body, an expression, a `title` prop — because over-reach here fails the build on a component nobody may edit. Two of its bounds were found **unheld by deliberate mutation** and only then written properly: the quote tracking, whose first two controls were unobservable (the `}` closing an expression also clears the buffer, so an early close reports nothing either way) and which is now held by markup built inside a **template literal**, the shape `FeeSchedule.astro` actually uses; and the unterminated-tag branch, whose first control used `a < b`, which is not a tag opening at all, so disabling the branch left every control green. All 13 mutations are held now, each by a named control.
- `node --experimental-strip-types scripts/service-area.test.mjs` — **read it whenever `src/lib/serviceArea.ts` changes** (#73). The only one of the six that tests *site* code rather than a gate, and it is here because that module decides whether a rider is quoted a fare at all and at which market's rates. It imports the **real** module — node strips the types, so there is no second copy of the maths to drift — and it is wired into `test:gates` with `--experimental-strip-types` for Node 22; CI runs Node 24, where stripping is already the default and the flag is still accepted (verified on both, 22.14 and 24.19). Three of its rules are easy to write subtly wrong and silent when wrong: the boundary is **inclusive**, the overlap tie-break is **document-id order** (reproduced by sorting rather than trusted from the wire), and — the one worth the file — **`outside` requires every area to have published a usable circle**. Miss that last one and §3.5's "We're not in that area yet." fires whenever an admin leaves a radius blank: every other bug here is wrong by a number, that one is wrong by a sentence. The South Florida block uses production's live circle rather than a round fixture, and all four rules were confirmed to fail under deliberate mutation before the controls were trusted.

`npm run build` runs eight things in order, and any one of them fails the build. The seven control sets above run **before all of them** — `npm run checks` starts with `npm run test:gates` — and are deliberately not numbered among them: six of the seven test the gates rather than the site, and the numbering below is cross-referenced throughout this file.

1. **`scripts/check-route-parity.mjs`** — every route under `src/pages` has its `/es/` twin. `404` and `redirect` are exempt by name (single file, language switched client-side). Routes whose twin is not built yet sit in a `PENDING` map naming the ticket that retires them; an entry whose twin now exists fails, so the list cannot go stale.
2. **`scripts/check-copy-gate.mjs`** — gated and never-claimed strings (`docs/copy-map.md` §5, on the unmerged `copy-map/en-es` branch) must not reach the site. Scans `src/` and `public/` and fails on a Greek or Cyrillic letter, which in EN/ES copy is a homoglyph hiding a gated word. It reads each file **twice**: once raw, line by line, and once normalised through `scripts/copy-gate-normalise.mjs` — the same reading machine item 8 uses (#68), so a phrase broken across a tag, a *known* entity, a JS escape or a newline fails here, at the point of authorship, rather than after a merge. A normalised hit still reports a line, a range when the phrase crosses one, and names the view that found it. It declines the two views that can *invent* a phrase, so no `copy-gate-allow` pragma has to bless a phantom; those stay item 8's. The homoglyph check reads the raw line **and** every normalised view, so a confusable introduced as an escape or a character reference is caught rather than decoded and thrown away (#80). The normalised reading **accuses**, with one deliberate exception opened by #82: a pattern may declare a `permits` phrase, and a hit is **withdrawn** when a non-fabricating view reads that permitted phrase over the same bytes. §5 has exactly one — "no surge today" — and it used to be a negative lookahead on the forbidden pattern, which held only for the bytes the lookahead saw: an `&nbsp;`, a wrapped line or a bolded word each failed the build on copy §3.4 expressly allows, while every view could see it was permitted and none was asked. Withdrawal is the only thing in either gate that turns a failure into a pass, so it is bounded four ways (only a pattern declaring `permits`; only a *positive* reading of §5's own permitted words, never the absence of the forbidden one; only a non-fabricating view, so the dist gate's phantom-inventing views may accuse but never excuse; and only over overlapping bytes) — the argument is on `permissionsIn` in `copy-gate-normalise.mjs`, and both directions are proved through both gates by `copy-gate-patterns.test.mjs`. One limit remains: **one** of the normaliser's tables is still finite, the ~2200 HTML5 **named** references of which it holds a few dozen, so a browser-known separator outside that table is a miss here and only the dist gate's fabricating view sees it (#80 closed the other two: invisible characters are now the Unicode property rather than eight of its members, and numeric references now follow HTML5 — unbounded digits, optional semicolon). Which of its files are read **as markup** — i.e. get the tag views — is settled by #81 and turns on whether the file is *served* rather than on its extension: everything under `public/` ships into `dist/` byte for byte, so all of it is read as markup, while under `src/` only the markup syntaxes are (`.astro`, `.html`/`.htm`, `.xhtml`, `.svg`, `.xml`, `.md`, `.mdx`). A `.ts` is compiled, not served; its `<` is a generic, and every `innerHTML` assignment in this repo is written inside a `.astro` component, which *is* read as markup here. A `.json` or `.yml` under `src/` is excluded on a **different** ground — there a `<` really is a tag — namely that nothing under `src/` is served, so it reaches a reader only through a `.astro` component or through the build, both of which are read as markup. That is a lost authorship-time backstop, not a production hole. Files it skips are named as `not read:` on every run. Its value is the file-and-line failure at authorship time, and it owns the per-line `copy-gate-allow` escape hatch — which covers the line a match **starts** on; see the script header.
3. **`scripts/check-env-example.mjs`** — `.env.example` and `scripts/env-required.mjs` name the same six variables, as an exact set in both directions (#70). It exists because `.env.example` only helps while it stays true: one that has quietly fallen a variable behind is *worse* than none, since a contributor copies it, gets a `.env` that looks complete, and fails at `npm run build` on a variable nobody told them about. It reads **names only and never a value** — that is what keeps it from being a third answer to the question `check-env.mjs` already answers (#72's subject). It cannot say what the build will see: no precedence across `.env.local` and the mode files, no `process.env` overlay, no quote stripping. It is asking a different question about a different file — `.env.example` is committed, hand-written, and loaded by nothing; Vite never reads it. Needing neither Vite nor secrets, it runs on a pull request, which is where the drift it catches is introduced. Strict in both directions on purpose: a superset rule would let a new variable reach `.env.example` and `deploy-all.yml` while missing `REQUIRED`, which is the exact drift #70 was filed over.
4. **`scripts/check-deploy-env.mjs`** — the "Create env file" step in `.github/workflows/deploy-all.yml` writes exactly the `REQUIRED` names, each from its own same-named secret, into `.env`, truncating once and appending after (#90). That step is the **only** thing that puts a value into the deploy's `.env`, and it was the third place a required name must appear with nothing asserting it. Miss the line and items 1–3 all pass, your local build passes off your own `.env`, and item 6 then fails **on `main`, after the merge**, reporting a missing *secret* when the secret exists and the workflow line does not — the cause named is not the cause. It does **not** parse YAML, because this job installs nothing (#41); it anchors on the step by name and reads the `echo` lines in the block that follows. Anchoring also means no YAML *sample* elsewhere in the repo can be read as the real thing — #71 deleted the one `docs/deployment.md` carried, which nothing asserted and which had drifted from the real file in every one of the seven steps it showed; that document points at the workflow now — and a leading `#` inside a `run:` block is a shell comment, so skipping those lines is correct rather than a blind spot. It recognises **one** line shape, and a line it cannot read is reported as unrecognised on its own line number rather than counted as a missing variable — naming the wrong cause is the fault this gate exists to remove. It also asserts the redirection (`>` once, then `>>`: a second `>` writes a `.env` holding one variable, and the deploy then fails naming five secrets that all exist) and that each name is written from `secrets.<the same name>` (a crossed pair is non-empty and printable, so it passes item 6 and fails only in the browser). The fourth place — the **GitHub Secret itself** — no gate here can see; item 6 still catches it on deploy, and with this gate green "missing or empty" there now means the secret.
5. **`scripts/check-astro-prose.mjs`** — a **text node** in an `.astro` template must not contain prose; rendered body copy comes from `src/i18n/` (#88, deciding #79). #68 gave the source copy gate the dist gate's normaliser, so a §5 phrase split across a tag, an entity, an escape or a newline now fails at the point of authorship — that **polices** prose typed straight into markup, it does not stop it existing. The convention that it should not exist was already carried by four documents (`docs/architecture.md`, `docs/components.md`, the `new-page` skill and the `page-consistency` agent, whose check 4 is literally “Copy lives in `src/i18n/`”) and was still **an agent a human has to remember to run**, which is the assumed-guard shape #59 is about. This removes the surface instead of watching it. **Attributes and props are out of scope, and that is a decision rather than an omission**: all 24 page files pass literal EN/ES `title` and `description` to `BaseLayout`, because #37's review **deleted twelve such keys from `src/i18n`** for duplicating the page files — a rule covering attributes would reverse a decision already taken on evidence. It finds text nodes by running the copy gate's own `opensTag`/`tagEnd` for their **complement**, imported and never re-written, for the reason #57 gives for one pattern list; the one thing it must get right is that markup and expressions **interleave** — most of this site's markup is built *inside* an expression (`LegalDocument`, `BaseLayout`, `AboutPage`, `PreRegistrationForm` all render through `.map`), so a reader that skipped from `{` to `}` would leave the main surface unscanned while appearing to cover it. **What counts as prose was chosen by measurement, not in advance**, and the measurement contradicted the ticket: over all 35 `.astro` files there are 11 non-blank text nodes, ten of them a `→` glyph or a bare `:`, and one `Footer.astro`'s copyright — so “two or more whitespace-separated word characters” fires on it at zero false positives while “a space between two **letters**” does not fire at all, because `2026` is digits. The hatch is #41's pragma discipline through the **same reader**, now parameterised by token; the token differs (`astro-prose-allow`) because it **has to** — item 2 scans `.astro` too and fails on a `copy-gate-allow` that matches nothing, so a shared token would have every prose pragma reported as dead by the other gate. It ships with **zero live entries**, which is why all of its behaviour is proved by control rather than by a live user. Dependency-free and network-free, so it runs on a pull request. Its stated limits are its own header's: `{"About YeRide"}` in an expression is **not** covered (a text-node rule is evaded by moving the string into one; the threat model is the accident, and §5's gate still meets a forbidden claim on the way out), `.md`/`.mdx` are not covered because none exist, and a one-letter tag name is the same ambiguity #99 documents — milder here, since a swallowed span can only make this gate read *less* text, so it can hide a text node but never invent one.
6. **`scripts/check-env.mjs`** — the six `PUBLIC_*` variables are present, non-empty and printable ASCII, and `PUBLIC_API_URL` ends with its slash. The printable-ASCII rule is a whitelist on purpose: an invisible character (a paste artifact like U+200E or U+00AD) survives `dotenv` and reaches the bundle, where it stops a URL parsing at all, and a blocklist of such characters cannot be finished. Astro inlines these at build time, so one that is not there becomes a falsy literal — `undefined` where the key is absent, `""` where it is present but empty — and Rollup then folds away the branch that tested it: an empty `PUBLIC_API_URL` ships a pre-registration form whose submit path no longer exists in the bundle, off a green build. The production trigger is the *empty* case, not the undefined one — a renamed or deleted GitHub Secret interpolates to `""` in `deploy-all.yml`'s "Create env file" step. It reads the environment through Vite's own `loadEnv`, so it sees exactly what the build will see (`.env` → `.env.local` → `.env.production` → `.env.production.local` → `process.env`, with an empty value in a later source blanking a non-empty one from an earlier). It needs both `npm ci` and the secrets, so it cannot join `checks.yml`. Run it alone with `npm run check:env`.
7. **`astro check`** — a type error fails the build.
8. **`scripts/check-dist-copy-gate.mjs`** — the same §5 list run over `dist/` **after** `astro build`, through six views of **every** scanned file (two of which the source gate declines because they can fabricate). Everything under `dist/` is publicly fetchable, so since #81 everything under `dist/` is read as markup — the extension says nothing about whether a browser will parse the bytes as tags, and a bundle assigning `Insur<span>ance</span>` to `innerHTML` was the hole that proved it. #81 paid for that in minified code, where `r<t.length` swallowed to the next `>` — 22,096 bytes of this build's bundles, the longest single span 16,251 — cutting **both** ways: a claim inside a swallowed span was **missed** (the plain view does not rescue it, because to the plain view the claim is still split), and a swallowed span *deleted* welded two identifiers into a phrase nobody wrote. **#99 closed both**, and not with the length bound its title proposed: the longest *genuine* tag this repo emits is 2,825 bytes of SVG path data, so no length separates a real tag from a comparison, but **shape** does. `TAG_OPEN` in the normaliser now reads the tag **name** and requires it to end where a tag name ends — at whitespace, `/` or `>` — so `r<t.length` is rejected before the scan starts, exactly as a browser rejects it. All 22,096 false bytes are gone, and an audit of all 3,236 tag spans in **this** build finds every survivor to be genuine markup — a measurement, not a guarantee: a **one-letter** tag name (`a<i>b`, `x=a<b>c`) is valid minified JavaScript and valid markup alike, no syntactic rule can separate those, and the dist gate's `ALLOWED` list stays the answer if one ever ships. Both gates import **one** pattern list, `scripts/copy-gate-patterns.mjs`, **one** normaliser, `scripts/copy-gate-normalise.mjs`, and **one** file-type table, `scripts/copy-gate-files.mjs` — never two of any, because a pattern, a transform or a file type present in one gate and absent from the other reads as covered when it is not. That last one is not hypothetical: the two extension lists had silently drifted (`.yml` in one, `.xml`/`.webmanifest`/`.map` in the other) until #81 merged them. This is the layer that measures the actual promise — a forbidden claim must not reach the shipped site. Since #68 gave the source gate the same reading, what only this gate can still see is narrower and worth naming: **vendored** files this repo does not author; copy **composed by the build** out of parts innocent in the source (`{copy.lead} {copy.tail}` is two strings here and one phrase in the built HTML — the one residual a PR author hits by *accident*), including literal concatenation Rollup folds (`"insur" + "ance"`); and the two normalisation views that can invent a phrase, which the source gate declines and this gate blesses by hand. It also reads the compiled `.js` bundles as markup, which the source gate deliberately does not do to the `.ts` they came from (#81). Source pragmas are stripped by the build and cannot be seen from here, so it carries its **own** allowlist keyed to the hash-free path, the matched text and an exact count; an entry that stops matching, or matches a different number of times, fails. It also honours §5's `permits` withdrawal (#82, described under item 2) and is where that mechanism is most load-bearing, because this is the gate that takes the two fabricating views: a view that can invent a phrase may **accuse** here and may never **excuse**, or `no surge<i></i>today` — the permitted phrase to `tags-as-space`, "no surgetoday" to a reader — would launder through the one layer that measures the shipped promise. Run it alone with `npm run check:dist` (needs a `dist/`).

`.github/workflows/checks.yml` runs the seven control sets and then items 1–5 on every pull request **and on every push outside `main`** — the `push` trigger is not redundant with the `pull_request` one and closes a silent hole found on #104: `pull_request` runs against the head-merged-into-base ref, which GitHub **cannot build when the PR has conflicts**, so a conflicting PR gets no run at all — an absence rather than a failure, and "no checks" reads at a glance like "no problems". A branch can always be checked on its own, so `push` covers exactly the case `pull_request` structurally cannot. It is it is dependency-free by design, and items 6–8 all need `npm ci` against the private registry (item 6 reads the environment through Astro's own Vite), with item 6 additionally needing the secrets a PR does not have. `deploy-all.yml` runs the full chain on `main` and gates deployment on it, so items 6 and 8 are pre-deploy backstops rather than PR-time ones.

Items 3, 4 and 6 share **one** list of variable names, `scripts/env-required.mjs` — never three, for the reason #57 gives for one pattern list and #68 for one normaliser. It is data and one pure function with no imports, because items 3 and 4 must stay installable-free; the Vite-shaped knowledge stays in `check-env.mjs`. Copies of six names would drift the moment a seventh arrived, and every gate would still pass, each checking its own half. Items 3 and 4 are separate scripts over that one list rather than one script with two legs: they read files of different kinds — a committed dotenv file and a YAML `run:` block — and `check-env-example.mjs` makes a structural claim about never becoming a third reader of the *environment* (#72) that a workflow parser inside it would falsify. Two gates over one hub cannot drift; two copies of the hub can.

One further gate runs **outside `npm run build`**, because it needs the network:

- **`scripts/check-fee-labels.mjs`** — every charge id, service area and ride tier id `getFeeSchedule` publishes has a site-authored EN/ES label in `src/i18n/feeLabels.ts` (tiers were added by #65: they name the rate card's rows on `/fees` **and** the result list on `/fare-estimate`, which reads the same `rideServices` documents through `estimateFares`). It asks the live endpoint (all areas, not just the default), so it cannot live in `npm run checks` without coupling every local build and every PR to a third party's uptime. It runs on deploy (`deploy-all.yml`, before the build) and daily on a schedule (`fee-label-drift.yml`, which opens an issue on drift, since drift arrives from the admin console between deploys). It **fails on drift and skips when it cannot ask** — a missing `PUBLIC_FEE_SCHEDULE_URL` or an unreachable endpoint prints a `SKIPPED` line and exits 0. Run it by hand with `node scripts/check-fee-labels.mjs [url]`. It is the **one** script here that reads the environment without going through Vite, and #72 settled that deliberately: it runs in `deploy-all.yml` *before* `npm ci`, so it cannot import Vite the way gate 5 does, and its `fromDotEnv()` reads `.env` alone and verbatim — no `.env.local`, no mode files, no quote stripping, and a raw `startsWith` that cannot see an `export `-prefixed line. That divergence costs nothing in CI, because **no CI path reaches it while the secret has a value**: `deploy-all.yml` and `fee-label-drift.yml` both hand the variable to the step in its own `env:` block, so `process.env` answers first. The one fall-through is an **empty** secret, and it is harmless by construction — `fromDotEnv()` then reads the `.env` that same workflow just wrote from that same empty secret, so both readers return `""` and the run skips. It is otherwise a local-run convenience, and the one way it could be wrong — verifying a different endpoint than the build would ship against — is now disclosed rather than documented away: **a run that resolved a URL prints it and the source it came from**, on the success, failure and unreachable-endpoint paths alike. The single path that prints neither is the one that resolved no URL, and it names the four things it did not read instead — the same disclosure for the only case with nothing to name.

## Environment Variables

All six are `PUBLIC_` (client-side) and are injected in CI from GitHub Secrets. All six are **required**: `npm run build` fails on a missing or empty one (gate 6 above). `npm run dev`, `npm run checks` and `npx astro check` need none of them, so a docs- or copy-only change can still be type-checked without keys.

**The list is `.env.example`** — committed (`.gitignore` carries `.env*` with `!.env.example`), and the only place the six names and their shapes are written as a list. `cp .env.example .env` and fill it in. This file used to restate them and six other documents restated them again; #70 ended that, because the list existing in seven places and being authoritative in one is not a hypothetical cost — #69 needed three review rounds to get those seven right, and round three had to abandon reading from memory and sweep with `grep`. What stays here is what a list cannot carry: why each variable exists and what specifically breaks without it, which is gate 6 above and the `breaks` strings in `scripts/env-required.mjs`.

Only `PUBLIC_API_URL` carries a real value in `.env.example`; the other five are secrets on deliberately invalid placeholders. Those placeholders do **not** fail the build, and that is worth knowing before trusting a green one: they are non-empty, printable ASCII and well-formed, which is all gate 6 asks — it checks that a value exists, never that it works. `cp .env.example .env && npm run build` is green against five fake keys and serves a site with no map, no fare and `/fees` in its error state. The file gets you a build, not a working site. That real value is **not** `https://api.yeride.com/`, which every one of those seven documents used to show and which is **NXDOMAIN** — it has never resolved, so a contributor who followed the docs was configuring a host that does not exist. Production posts to a Cloud Run hostname, already public: Astro inlines it at build time and it is readable in the shipped HTML of `/drivers/`.

Adding a new env var is a **four-place** change, and three of the four are now asserted on the pull request. It requires editing `.github/workflows/deploy-all.yml` (the "Create env file" step writes `.env` line by line, `>` then `>>`) **and** adding the GitHub Secret. A var that is required for a page to work also belongs in `REQUIRED` in `scripts/env-required.mjs`, with what breaks when it is absent — that list is what stops a missing secret from being silently empty in production — **and** in `.env.example`. Gate 3 asserts `.env.example` against `REQUIRED`, gate 4 asserts the workflow step against `REQUIRED` (#90), and both run on every pull request. The **secret** is the fourth place and the only one nothing here can see; gate 6 catches it on the deploy, off the empty string it interpolates to.

## Architecture

**Framework:** Astro 5 (static output, zero JS by default)
**Styling:** Tailwind CSS 3 via `@astrojs/tailwind`
**Deployment:** GitHub Actions → GitHub Pages on push to `main`

### Two independent backends

The site talks to two unrelated services; don't conflate them.

1. **Pre-registration** (`src/components/PreRegistrationForm.astro`) — plain `fetch` POST to `${PUBLIC_API_URL}v1/auth/register`, which is *yeride-admin-api*, not yeride-functions. It writes a `whitelist` row; it does not create an account. The form logic is a **bundled** `<script>` that imports its copy from `src/i18n/formCopy.ts` and reads `import.meta.env.PUBLIC_API_URL` directly (wayfinder #37 replaced the old `is:inline` + `define:vars` script). Because that value is **inlined at build time**, an empty `PUBLIC_API_URL` strips the whole submit path from the bundle; `scripts/check-env.mjs` fails the build rather than let that ship (#59).
2. **Fare estimates** (`src/components/FareEstimatePage.astro` + `src/lib/fareEstimate.ts`) — Firebase **callable function** `estimateFares`, hardcoded to region `us-east1` in `src/lib/firebase.ts`. The service area is **resolved from the rider's pickup** (#73) by `resolveServiceArea` in `src/lib/serviceArea.ts` — Haversine against each area's circle, which `getFeeSchedule` publishes since yeride-functions#45 — with `us-fl-south-florida` as the **fallback**, not the answer. It returns three states, not two: `unknown` (an area publishing no usable circle, or an unreachable endpoint) falls back and keeps #62's "Priced for" disclosure, and only `outside` — where *every* area published a circle and none contains the pickup — ships §3.5's "We're not in that area yet." A two-state version would put that sentence on screen whenever an admin left a radius blank. The component script loads Google Maps libraries (`maps`, `places`, `marker`, `routes`) via `@googlemaps/js-api-loader`, resolves pickup/dropoff, computes distance + duration, then calls `getEstimates()`.

   `estimateFares` **no longer returns** `appCharges`/`appChargesTotal` — they were withdrawn from the endpoint (yeride-functions#47). `ServiceEstimate` had **deliberately declined to declare them** (wayfinder #38) because they are the *driver's* cost in both payment flows, never the rider's, and that refusal is precisely what the withdrawal was built on: yeride-functions#37 went looking for a reader of those fields, found this site declining them by name and no program anywhere reading them, and took the whole surface off the wire. The reasoning is written into `src/lib/fareEstimate.ts`; read it before adding the fields back.

Firebase Auth and Firestore are not used — only `firebase/functions`.

### Page structure — one layout, thin pages

Every page renders through the single `src/layouts/BaseLayout.astro` (wayfinder #35). **No
page declares its own `<html>`/`<head>`**, and no page carries inline header or footer
markup — `Header.astro` and `Footer.astro` have one caller each, `BaseLayout`. A navigation
or footer change is therefore one edit, in one place.

Every route keeps the page file thin — `BaseLayout` plus one component that holds the whole
body (`HomePage`, `DriversPage`, `RidersPage`, `FeeSchedule`, `FareEstimatePage`,
`LegalDocument`, `ContactPage`, `AboutPage`) — with the copy in `src/i18n/`. Follow that shape
when adding a page. `about` was the last route still carrying its pre-redesign body and shipped
on the shape with [#85](https://github.com/yeapptech/yeride-website/issues/85), once
yeapptech/yeride-brand#22 landed the authored ES identity paragraph it was blocked on outside
this repo. **No route is exempt any more, and gate 1's `PENDING` map is empty** — an entry
there is now a claim that a route ships in one language, so add one only with the ticket that
retires it.

`/404` and `/redirect` are the two exceptions to "every route ships EN and ES": they are one
file each, serving **both** languages, because GitHub Pages answers every missing path with a
single root `404.html` and `/es/404` is therefore unreachable. `BaseLayout`'s `bilingual`
prop ships both languages of the header and footer alongside the page's own two halves and
reveals one from `location.pathname` — chrome included, since Spanish content under English
navigation is the half-translated page #62 and #65 were re-opened over. The mechanism, and
the two ways it fails silently, are in `docs/components.md` under `BaseLayout`.

`navBar.astro`, `src/data/navData.ts`, `src/styles/main.css` (Open Props from unpkg) and the
`https://cdn.tailwindcss.com` script tags were all removed by #35. Tailwind comes from the
`@astrojs/tailwind` integration and the brand preset alone — do not re-add a CDN tag.

Line endings are mixed and there is no `.gitattributes`: some older files are CRLF, most
newer ones LF. Editing a CRLF file with a tool that rewrites it wholesale will convert it
and bury your real change in a full-file diff.

### Other integrations

- **No contact form, and no Tally** — `/contact` publishes `support@yeride.com` and nothing
  else (#39 amended copy-map §3.7). The embedded Tally form was dropped: its questions lived
  inside Tally, the last user-facing copy on this site outside the repo and invisible to both
  copy gates, and Tally has no runtime localisation, so `/es/contact` would have needed a
  second form authored and kept in sync by hand forever. Removing it also deleted a named
  processor from the privacy policy. **Do not re-add a third-party form embed.** If
  structured intake is wanted, copy `PreRegistrationForm.astro` — markup and per-field EN/ES
  copy in `src/i18n/`, posting to an endpoint YeRide owns
- **Nunito** — the brand typeface, self-hosted via `@fontsource-variable/nunito` and imported once in `BaseLayout`; exposed as `font-brand`. The old per-page Google Fonts link to Inter is gone (#35)
- `src/pages/redirect.astro` — bounces to the `yeride://register` deep link. Not bare HTML:
  it renders through `BaseLayout` like everything else (#35), in `bilingual` mode (#39)
- **URL aliases the mobile app depends on** — `redirects` in `astro.config.mjs` maps `/privacy`
  → `/privacy-policy`, `/es/privacy` → `/es/privacy-policy` and `/support` → `/contact`
  (wayfinder #44). These are not cosmetic: yeride-mobile links `yeride.com/privacy` in-app and
  submits it as the store-listing privacy URL, and a missing `/support` was a 2025 App Store
  rejection. Do not remove or rename them without changing the app first. They live in the
  config, not in `src/pages`, so the route-parity check is not asked to find `/es/` twins for
  aliases.

## Coding Conventions

- Astro components (`.astro`) with scoped `<style>` tags
- **Body copy lives in `src/i18n/`, never as literal text in an `.astro` template.** Since #88 this is *enforced* rather than conventional — gate 5 fails the build on a text node containing prose. Attributes and props are deliberately **not** covered: per-page `title` and `description` stay on the page files, which is #37's decision and not an oversight
- Tailwind utility classes directly; **never use `@apply`**
- Minimize client-side JS; `client:*` directives only when hydration is genuinely needed
- Mobile-first responsive design (`sm`, `md`, `lg`)
- Conventional Commits (`feat`, `fix`, `docs`, `chore`, …)
